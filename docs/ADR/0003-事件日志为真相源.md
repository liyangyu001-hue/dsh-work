# ADR-0003 · 事件日志作为真相源

- 状态：已采纳
- 日期：2026-10-19

## 背景

任务状态会被三处写入动机影响：人按完成、AI 交回、系统巡检。若各处直接写 `work.json`，会立刻出现三类问题：并发覆盖、无法解释"为什么变成这样"、崩溃后状态不明。

## 选项

- **A. 直接改快照文件**：简单，但无历史、易覆盖、难调试。
- **B. SQLite**：可靠，但用户看不懂、无法手改、无法 git diff。
- **C. 快照 + 只追加事件日志**：稍复杂，但历史完整、可回放、人可读。

## 结论

选 **C**。

- `journal.ndjson` 是真相源：每行一个 `Intent`，只追加不改写。
- `work.json` 是可随时重建的折叠快照。
- 状态变更 = `apply(doc, intent)` 纯函数。同一串日志必然得到同一个 `doc`。

## 后果

- 好处：崩溃恢复、撤销、归因（这条是人是 AI 提的）、审计都免费得到；数据可 diff、可手改。
- 代价：日志会涨，需要折叠；`apply` 必须是纯函数，禁止在里面读时钟/IO/随机数。
- 约束：**所有 `apply` 分支必须有单测**；新增 Intent 必须同时补「非法迁移被拒绝」的测试。
- 将来接眼球追踪时，只是多一种产生 `Intent` 的来源，存储层不需要动。
